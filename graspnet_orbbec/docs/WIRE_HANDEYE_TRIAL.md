# 037K线材识别与手眼联调

本入口连接本地SAM2/端子模型、原始RGB米制定位和PIPER X法兰坐标。识别入口只输出**基座坐标及工具补偿位姿预览**；另增加离线连续逆解规划和独立的分步试验执行器。执行器默认只检查文件，必须现场复核并显式使用执行参数才发送指令；目前尚未完成真实抓取验收。

## 冻结输入

- 手眼工程：`/home/ning/PIPER X/hand-eye-calibration`。
- 结果：`reports/dc1_037K_20261030_calibration_01`，30训练/11验证。
- 预览选用PARK；验证平移RMS 5.418mm、最大9.516mm。这是固定棋盘一致性，不是独立绝对定位精度，也不是抓取成功率。
- 相机：CC1N162037K，640×480/MJPG，原始Brown畸变RGB。
- 反馈：`get_flange_pose`对应的被动CAN解码，单位m/rad，`Rz @ Ry @ Rx`，基座到法兰。禁止以TCP反馈替代。
- `configs/wire_handeye_037K.json`冻结了结果、内参和会话的SHA256。任何一份文件改变即拒绝加载；不改写原标定报告或数据集。
- 用户在本次联调确认同一台机械臂、相机安装未变；换臂或重装相机后必须重新核对/标定。

## 现阶段定位方式与限制

当前使用**同一张原图中棋盘的平面PnP**，不使用尚未验收的深度几何。自动检测8×5内角点，20mm方格，经典算法失败时尝试SB；两者仍要求完整40角点、正深度和重投影RMS≤1px。棋盘遮挡或重投影超限时，视觉识别可以保存，但不输出基座抓取位置。

像素先经`cv2.undistortPoints`恢复RGB射线，再与平面求交。线材夹持中心的高度必须实测，并确认局部线身平行于棋盘面：

`线材中心相对印刷面的高度 = 线材支撑面的高度差 + 线材半径`

朝相机为正。棋盘背板厚度也必须计入；线材拱起、悬垂、经过高低不平支撑时，此模型不成立。没有填写高度时只能得到**棋盘面投影**，输出`surface_projection_only=true`。

确认金属/绝缘交界后，沿三维中心线弧长向线身后退10mm，再求垂直闭合方向。变换链为：

```text
T_base_rgb = T_base_flange @ T_flange_rgb
p_base = T_base_rgb @ p_rgb
T_base_flange_goal = T_base_grasp @ inverse(T_flange_grasp)
```

工具坐标定义：X为夹爪闭合轴，Z为朝支撑面的接近轴，Y补成右手系。30mm预抓取净空是**位姿预览**，没有碰撞/可达性验收，不能直接执行。

## 使用

从任意目录均可运行脚本；参数中的相对路径仍相对于当前终端目录。以下先切换到项目：

```bash
cd /home/ning/orbbec/graspnet_orbbec
bash scripts/run_wire_grasp.sh audit
```

采图前在本机准备已启用的CAN。若DOWN，由操作者执行：

```bash
sudo ip link set can0 up type can bitrate 1000000
```

保持机械臂和目标静止，棋盘和目标端部同时完整可见，避免线材压住棋盘角点。采图不使能、不运动，仅复用标定工程的被动接收器与C++相机采集：

```bash
bash scripts/run_wire_grasp.sh capture --out output/wire_grasp/trial_001
```

4秒完整反馈必须满足原标定门槛：图像前后各0.5秒覆盖、邻近反馈间隔≤20ms、平移变化≤0.5mm、旋转变化≤0.1°。失败保留日志，但不生成`pair.json`。接收时间配对不代表曝光同步。

打开该配对快照的自动识别窗口：

```bash
bash scripts/run_wire_grasp.sh preview \
  --snapshot output/wire_grasp/trial_001 \
  --same-installation-confirmed \
  --tool configs/wire_tool_piper_x_nominal.json
```

窗口沿用现有交互：自动SAM2识别；Shift+左键在左侧原图确认金属/绝缘交界；绿色点显示有尺度的夹持中心预览；S保存，Q退出。识别和交界必须来自同一冻结快照。相机实时改变、线材移动或重新采图后，重新确认交界。

若SAM2只分出绝缘线身、自动逻辑因金属仍向外延伸而排除了该掩码端部，手眼窗口允许操作者在该处确认**交界**，新候选编号为J1等。仅恢复点击附近12像素内、路径无歧义的线身路径；不会把它改标为物理金属尖端。命令行对应`--boundary-point X Y`。普通二维窗口的端点排除规则不变。

`--roi X1 Y1 X2 Y2`将自动识别限制到明确工作区；坐标为640×480原图整数像素。推理结果、端子掩码/框和提示点恢复到原图坐标；裁剪边缘截断不当作真实端点。不要用极窄工作区切掉金属端子或所需10mm线身。默认二维识别仍处理全图。

已测得高度后加入`--center-height-mm 实测值 --support-relation-confirmed`。不能为了消除阻塞填写猜测值。交界尚不能在当前权重可靠漏检/误检的情况下全自动确认；A/B几何端部不是金属语义真值，YOLO高分也须复核。

命令行批量复现：

```bash
bash scripts/run_wire_grasp.sh recognize \
  --snapshot output/wire_grasp/trial_001 \
  --same-installation-confirmed \
  --boundary A 原图X 原图Y \
  --out output/wire_grasp/trial_001_recognition
```

`recognition.json`保存每候选的交界、米制路径抓取点、基座坐标、方向、工具补偿及阻塞原因。`robot_pose_valid=false`、`executable=false`始终保留；本入口不发送机器人命令。

## 原厂夹爪与TCP

官方SDK默认TCP偏置为`[0,0,0,0,0,0]`，即法兰；`set_tcp_offset`只保存当前SDK实例的输入。示例100mm不是原厂夹爪的自动预设。

- SDK固定版本说明：<https://github.com/agilexrobotics/pyAgxArm/blob/d90e234ba8e408cfa964b38aa9120b3131fc9f85/docs/piper/piper_api.md#tcp-related>。
- 官方模型：<https://github.com/agilexrobotics/agx_arm_urdf/blob/680fa925cd00db7e2628563d2edc5540963045de/piper_x/urdf/piper_x_with_gripper_description.xacro>。原样快照保存在`docs/vendor/`。
- 模型中`link6 → flange_link`为单位变换；`flange_link → gripper_base`沿Z 4.5mm、绕Z 90°；两夹指参考原点在`gripper_base`前方138mm，开合轴对应法兰X。
- 所以模型夹指参考平面中点距模型法兰142.5mm。`configs/wire_tool_piper_x_nominal.json`可用于**名义参考补偿预览**，保留`verified=false`，不能称为实测TCP。

实际夹持中心可以在尖端之后数毫米；夹爪开度、夹指版本、垫片和安装方向均需核实。若把尖端后方的夹持中心对准桌面细线，尖端可能先碰桌。因此**平放场景用于坐标检查，不自动等同于可执行抓取场景**。真实夹持测试需要明确指尖净空，例如经过核实的抬高支撑和可进入的夹持段；支撑变化后重新测量局部高度。

若需实测固定测点偏置，可复用原标定工程的只读反馈记录器，由操作者手动以6～10个不同朝向对准同一刚性参考点，再离线拟合：

```bash
bash scripts/run_wire_grasp.sh fit-tcp \
  --feedback /真实反馈1.json /真实反馈2.json /真实反馈3.json \
             /真实反馈4.json /真实反馈5.json /真实反馈6.json \
  --out output/tcp_fit.json
```

拟合仅求同一刚性测点的位置，输出残差并拒绝退化姿态。不会把探针尖端自动当成夹持中心，也不会得到工具轴向。完整工具文件须提供实测`T_flange_grasp`、`verified=true`、`evidence`及规定的轴向定义。

## 独立试验执行器

`scripts/read_wire_robot_state.py`在原标定`robot-python`隔离环境中运行，纯被动接收关节、法兰、驱动和原厂夹爪反馈。`scripts/plan_wire_trial.py`在视觉环境中运行，将用户已确认的识别结果和真实起始反馈冻结为新路径文件，检查连续逆解、关节限位和每步变化。两个夹爪闭合轴对称朝向均可尝试；输出仍标记名义模型、未完成碰撞检查。

试验夹持参考默认取官方名义尖端后5mm，即法兰Z方向137.5mm。这是为了让线材进入夹指接触区的**试验参数选择**，不是实测TCP；指尖会比线材中心低5mm，因此必须先确认悬空及离支撑块的净空。预抓取点在线材上方30mm，抬升也为30mm。

`scripts/execute_wire_trial.py`必须在原标定`robot-python`中运行。省略`--execute`时只核对路径和来源指纹，不打开CAN。阶段分为：

- `--phase hover`：抬高、平移、调整朝向、到目标上方30mm停止，将夹爪设为25mm试验开度。
- `--phase grasp`：必须从已检查的悬停姿态开始；分步下降，1N闭合，再抬升30mm。闭合反馈不能证明已夹住，最终成功仍需真实观察。

真正发送需要`--execute --operator-reviewed --log 新日志路径`。它不自动使能、不复位、不标零、不回零。每个小步≤8mm/3°，速度为SDK的5%（不是绝对速度保证）；依靠真实反馈到位和停稳后继续。示教模式、驱动故障、陈旧反馈、起始姿态/关节改变、支路偏离或到位超时均拒绝继续；异常后尝试减速急停，不能把它理解为掉电抱死或保证维持姿态。日志故障也先尝试停止。

CAN发送白名单只包含低速线性位姿、≤1N夹爪命令和减速急停；使能、复位、标零、MIT和高速指令被拒绝。路径来源文件指纹改变即拒绝加载。

#### 已审查的小幅起始调整例外

**实机更新：本轮该首阶段未通过6秒到位检查，已保护停止并锁定旧路径。下述是历史设计说明，不是可重试的已验收操作；尤其前几个中间关节目标仍越出名义限位。后续应先审计恢复姿态与厂家ROS2/MoveIt2规划。**

本轮重启后实际J2为−2.291°、J3为+2.586°，略超出SDK名义规划范围；保持原朝向直接上抬8mm的连续IK未通过，不能忽略误差直接执行。规划器可显式增加`--prepare-start`：仅在J2/J3越界不超过5°时，准备朝原名义区间内部0.5°的单调关节调整。其他关节目标不变，总调整≤5°、每步≤1°，不修改SDK关节限位。每个目标的名义FK单独计算，不能作为实测反馈。

执行器只在已验证的首阶段`prepare_start`内临时启用逐条精确关节白名单；普通抓取白名单仍拒绝J控制。每个小步额外要求实际关节误差≤0.2°，并等待实际位姿到达，再进行后续低速线性路径。首阶段真实起始关节与审查值的差不得超过0.1°。起始调整也必须纳入现场扫掠审查和该次运动授权。

原`CONTROL_RECOVERY_BLOCKED.json`保留，复位/模式切换工具继续受锁。若要执行本轮重启后的新路径，规划器必须显式绑定`--control-audit`：该文件记录原异常锁、真实保持使能及其后的被动复查指纹，并有现场稳定确认。执行器要求路径创建晚于审计、使用审计中的新起始反馈、所有证据未改变；仍须另有`--execute --operator-reviewed`和新日志，不自动恢复旧路径，也不因此认定原SDK复位异常根因已解决。

### 从示教切回CAN

对本台`S-V1.9-1/v189`，官方ROS驱动的`is_switch_seamlessly`分支为真，不能套用旧固件`exit_teach_mode`中的回零/复位/使能流程。

官方依据：<https://github.com/agilexrobotics/agx_arm_ros/blob/286633e0d2edb038ee3a1047d9feb7f614a1c076/src/agx_arm_ctrl/agx_arm_ctrl/agx_arm_ctrl_single_node.py#L245-L252>及同文件1180～1191行的实时关节保持分支。

`scripts/switch_wire_can_hold.py`默认只被动读取并预览报文。它仅允许已审计v189，取新鲜真实关节角，准备一次5%速度的位置保持目标；不发送历史抓取目标、回零、复位或使能。只有明确`--apply --operator-ready`才进行切换。发送内容限于本次实时角度对应的0x151及0x155～0x157，随后核对CAN模式、驱动状态和实际位姿变化；失败不自动复位重试。该动作需要现场人员准备，不能用断电试错替代。

实机补充：第一次保持式切换时操作者尚未真正退出拖动，控制器仍返回模式2。保护逻辑随后发送减速急停，操作者确认没有明显运动；被动反馈显示待机/急停。后来用户手动退出拖动，确认`teach_status=2`，急停状态仍为1。因此不能把v189的无缝切换支持理解为能绕过仍活动的物理拖动状态，也不能将该尝试视为切换成功。

`scripts/clear_wire_software_estop.py`仅准备恢复本轮明确记录的保护急停：要求发送记录、待机/急停、拖动记录已结束、驱动和夹爪无其他故障，并检查停稳。默认只读；独立获现场授权后使用`--apply --operator-ready`，只允许一次SDK `reset()`对应的0x150恢复报文，不发送使能、关节/笛卡尔目标或夹爪动作。解除急停后仍需重新读取模式并建立当前姿态保持，不能直接恢复旧抓取路径。

### 正常重启后的单次原位保持使能

本轮两次软件急停恢复均未通过，因此不再重试`reset()`。人工按设备正常流程重启后，先被动检查。`scripts/enable_wire_current_hold.py --post-restart-state 重启后只读报告 --out 新报告`默认只接收CAN和预览编码；要求正常待机、拖动未活动、六轴未使能、无驱动故障、反馈完整且连续停稳。重启后报告必须晚于本轮异常记录，并属于同一SDK与CAN通道。

现场另行确认后，只有增加`--apply --operator-ready`才执行一次：预置实时当前六轴关节角的5%位置保持目标、夹爪1N保持100mm开口、SDK使能六轴、重复同一关节目标。当前夹爪约101mm，因此可能轻微收拢约1mm。精确白名单限于该次实时角度的9条报文；不允许夹爪标零、复位、回零或抓取目标。SDK编码同时以独立单位换算复核，不能因软件限位裁剪而变成其他关节目标。

反馈验收要求正常CAN控制、六轴和夹爪均已使能、开度误差≤2mm，并连续0.5秒保持位姿。位姿变化超过2mm/1°、任一关节超过0.5°、驱动故障、反馈不完整或3秒内未完成使能均停止并尝试减速急停，不自动重试。抱闸未释放状态6只作为等待中的过渡状态，不能通过最终验收。使能尝试写入原控制异常锁；独立的旧恢复和抓取执行锁不会因使能成功自动删除。

该工具仅供本轮已审计v189与当前接近全开的原厂夹爪使用；它不是通用开机程序。成功后的真实反馈与现场稳定观察仍需保存，随后重新采图和规划，不能沿用重启前路径。

`scripts/read_wire_motion_limits.py --out 新报告`是另一种只读查询工具：会发送12条精确校验过的0x472参数读取请求，收集0x473/0x47C原始回复与SDK解码值；不建立SDK通信会话，不写参数、不复位、不使能或发位置目标。它与完全被动的状态读取不同，报告会分别记录读取请求与零运动命令。速度、加速度解析使用当前已审计SDK的0.01rad/s和0.01rad/s²换算，并保留原始字节供复核。
