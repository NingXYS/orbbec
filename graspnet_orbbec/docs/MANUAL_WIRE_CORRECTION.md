# 手眼预览中的线身纠正与交界确认

更新：2026-11-05。沿用[日常主手册](REAL_GRASP_STARTUP.md)的启动、采图和预览命令，无需增加启动脚本。

## 为什么Shift没有生成可用候选

Shift确认的是金属/绝缘交界，不会重新运行SAM2。同一可见线身可能被自动搜索产生的多个掩码重复覆盖，又与金属段、支架碎片形成歧义。此时即使YOLO检出了端子，交界仍会被拒绝。此前手眼窗口还拦住了普通鼠标纠正操作，现已接通现有手动提示分割。

## 操作顺序

自动结果清晰、目标实例无歧义时，仍可直接Shift+左键确认交界。出现大量背景、重复实例或Shift提示“实例归属存在歧义”时：

1. 在**左侧冻结原图**中，对目标的绝缘线身中段普通左键点一下；不要点端子、夹爪、支架或桌沿。等待右侧更新。
2. 必要时继续补线身正点，右键对确定不属于目标的背景补负点。不要把真实线身设为负点。拖框可重新限定目标，但会清空已有提示；当前固定场景优先试单点，过窄框可能失败。
3. 检查右侧掩码及中心线：只含目标线身、目标交界附近及向线身内至少14mm路径清晰，无粘连、分叉、交叉或断裂。满足时按 **V**，记录本次人工线身复核。无法判断时继续纠正或整理现场重新采图。
4. 再用 **Shift+左键** 点击真实金属/绝缘交界。检查粉色交界、绿色夹持中心和状态；没有真实尺度时只得到待定位候选，不能继续执行。
5. S保存、Q退出，然后按主手册选本次候选并只规划。仍有任何阻断时停止。

V不强行解除实例歧义。Shift先于V时可以记录清晰实例上的交界，但会保留 `visual_path_manual_mask_review_required`；核对后按V会重新计算已记录交界。新增补点、重拖框、R重识别或C清除后，原复核不能继承。

手动单点使用完整冻结原图作为SAM2上下文，不自动继承自动模式的窄ROI。拖框则使用现有带边缘余量的裁剪逻辑；窗口蓝框对应实际裁剪范围。所有提示、掩码和交界都使用完整RGB坐标，原图及手眼位姿不变；跨快照仍拒绝绑定。

手动纠正不重新运行YOLO，原青色端子标记可能消失；这不代表模型在新一轮漏检。人工交界不依赖模型检出，但必须通过实例、局部路径及来源复验。没有改变14mm算法、手眼/TCP变换或运动控制。

## 新增数据字段

`recognition.json`保持现有候选、实例与路径结构，新增字段如下：

| 字段 | 含义 |
|---|---|
| `automation.method=manual_prompts`、`manual_prompts=true` | 使用手动提示替换自动目标假设 |
| `automation.coordinate_space=original_rgb_pixels` | 提示使用完整原图坐标 |
| `automation.prompts` | 实际提交的box、points、labels；labels中1为正点、0为负点 |
| `automation.manual_mask_review` | schema_version=1，人工复核标记、实例ID、原图像素及实例掩码SHA256、操作者复核约定 |
| `grasp_policy.mask_origin` | 掩码来源，与automation交叉核对 |
| `grasp_policy.manual_mask_review` | required、passed及rejection_reasons复算摘要 |

掩码指纹由完整二值掩码的形状（NumPy int64字节）及uint8像素字节计算；图像指纹沿用原有BGR数组字节合同。该记录是本地一致性证据，不是防篡改签名，也不能代替真实场景判断。

最终视觉验收层从完整实例游程重建掩码并核对复核指纹，不能只看上游passed。手动结果缺少记录、图像或掩码变化、记录不一致时，追加 `visual_path_manual_mask_review_required`，禁止执行。旧自动结果的复核要求不变；旧手动结果重新纠正、核对并保存，不手补字段。

## 离线验证范围

测试覆盖手眼窗口中的正负点、V与Shift顺序、同快照绑定、未复核阻断、分叉/交叉/断裂拒绝、复核失效、最终层缺字段/证据变更拒绝及自动模式兼容。

历史真实照片仅用于复现：自动固定ROI曾得到14个歧义实例；线身单点提示可得到1个无歧义实例，模拟V/Shift事件可生成交界候选。该回放没有当前实测高度、有效现场确认或完整执行资格，不能用于直接抓取。运行结果见本地 `output/manual_boundary_review_20261105/`；没有连接或运动机械臂。
